## Project Overview

XPay merchant admin dashboard, based on Vue 3 + Vite 6 + TypeScript + Element Plus. Rebuilt from RuoYi-Vue-Plus frontend framework. Node >= 18.18.0.

## Commands

```bash
npm run dev              # Dev server (port 80, proxies to localhost:8078)
npm run build:prod       # Production build
npm run build:dev        # Dev-mode build
npm run preview          # Preview production build
npm run lint:eslint      # ESLint check (flat config)
npm run lint:eslint:fix  # ESLint auto-fix
npm run prettier         # Prettier format (printWidth: 150, singleQuote)
```

No test commands (vitest installed but not configured/used).

## Architecture

### Dynamic Routing (core pattern)
1. Login → `userStore.getInfo()` fetches user roles/permissions
2. `permissionStore.generateRoutes()` → requests `/system/menu/getRouters`
3. Backend returns menu tree → frontend maps string paths to `import()` lazy-loaded components
4. `router.addRoute()` injects dynamically

**Adding a new page**: just create a `.vue` file under `src/views/` and configure the menu path in the backend. Component mapping logic lives in `src/store/modules/permission.ts:loadView`.

### Directory Structure
```
src/
├── api/              # API modules by domain (xpay/system/workflow/monitor/tool)
├── store/            # Pinia stores (user/permission/settings/app/dict/notice/tagsView)
├── layout/           # Main layout (sidebar + topbar + tagsView)
├── views/            # Page components (xpay/system/workflow/monitor/tool/demo)
├── components/       # Shared components (22)
├── utils/
│   ├── request.ts    # Axios wrapper (encryption, dedup, token refresh)
│   ├── auth.ts       # Token storage (localStorage)
│   ├── crypto.ts     # AES encrypt/decrypt (CryptoJS, ECB + PKCS7)
│   └── jsencrypt.ts  # RSA encrypt/decrypt (JSEncrypt)
├── plugins/          # Global plugins ($tab/$modal/$cache/$auth/$download)
├── directive/        # Custom directives (v-hasPermi/v-hasRole)
├── lang/             # i18n (zh_CN/en_US)
└── hooks/            # Composables
```

### API Request Encryption
- Controlled by `VITE_APP_ENCRYPT` env var (enabled by default)
- Request: AES encrypt body → RSA encrypt AES key → `encrypt-key` header
- Response: detect `encrypt-key` header → RSA decrypt AES key → AES decrypt body
- RSA key pair stored in environment variables

### Styling
- **UnoCSS** (`uno.config.ts`) — atomic CSS (presetUno + presetIcons + presetAttributify)
- SCSS for global styles
- Element Plus dark theme support
- `virtual:uno.css` imported via Vite virtual module

### Auto-imports
- `unplugin-auto-import` — Vue/VueUse/Pinia/ElementPlus/VueRouter APIs available globally, no manual imports needed
- `unplugin-vue-components` — Element Plus components auto-registered on demand
- Type declaration files `auto-imports.d.ts` / `components.d.ts` are gitignored

### Environment Variables
- `VITE_APP_BASE_API`: `/dev-api` (dev), `/prod-api` (prod)
- `VITE_APP_ENCRYPT`: request encryption toggle
- `VITE_APP_RSA_PUBLIC_KEY` / `VITE_APP_RSA_PRIVATE_KEY`: RSA key pair
- `VITE_APP_CLIENT_ID`: OAuth2 client ID
- `VITE_XPAY_BASE_URL`: XPay SDK backend URL

### Dev Proxy
`/dev-api` → `http://localhost:8078`

## Pitfalls

1. **Don't manually import Vue/ElementPlus functions** — `ref`/`ElMessage` etc. are globally auto-imported
2. **package-lock.json is gitignored** — use npm consistently to avoid lockfile conflicts
3. **API encryption enabled by default** — ensure backend is running or temporarily disable for debugging
4. **el-dialog closeOnClickModal disabled globally** — set in `main.ts`
5. **Type declaration files not version-controlled** — auto-generated by Vite plugins
